**版本**：v2.0（2026-10-26 修订）

## 2. 关键技术决策

| # | 决策点 | 选定 | 理由 |
|---|---|---|---|
| D1 | 指令分发 | **主 switch，按 opcode 分组** | 代码生成是为性能服务的（rv32emu 的 `decode.c` 8,735 行是自动生成）；本项目 30 MIPS 足够，可读性和可调试性优先 |
| D2 | 指令语义复用 | **宏展开（参考 `RVOP()`）** | 避免"同一条指令在两个变体里行为不一致"这类最难查的 bug |
| D3 | CSR 组织 | **按功能分区：身份/trap/中断/计数器/PMP/MMU** | 参考 rvemu 的三分离（`csr` + `exception` + `interrupt`）；但**注意计数器是可写的**（v1.0 写成只读是错的） |
| D4 | 异常与中断 | **分离，但共用一个 trap 入口函数** | `mcause` 最高位区分两者，但进入路径共享代码，避免两条路径的位域操作不一致 |
| D5 | MMIO 路由 | **先判 RAM 区间，再查 256 项表** | 见 §3.4 的不变量。纯查表会撞车 |
| D6 | Sv32 | **实现，Gate 5 就要** | `rv32si-p-dirty` 是 Gate 5 的测试项，不是迷你内核才用。v1.0 把它排到 Gate 7 是重大误判 |
| D7 | PLIC | **实现最小版（单源 UART）** | Gate 6 要进 shell 执行命令 ⇒ 必须有 UART 接收中断。v1.0 说"不做 PLIC"与验收冲突 |
| D8 | 调试协议 | **自定义 JSON-RPC** | Debug Spec 面向 JTAG 外部调试器，实现它等于多写一个 DM 状态机 |
| D9 | 可视化形态 | **WASM 网页** | rv32emu 有先例（`docs/wasm.md`）；注意需要 COOP/COEP 头才能用 `SharedArrayBuffer` |
| D10 | Linux 启动 | **路线 A（M 模式直启）**，B 为加分 | 已定 |
| D11 | `tohost` 定位 | **ELF 符号表，监视物理地址** | 不同测试基址不同；spike 的 `htif.cc` 即如此 |
| D12 | 性能目标 | **解释执行，≥30 MIPS（关闭事件）** | 简单 switch 解释器在当代 x86 上通常 50–300 MIPS；真正瓶颈是每指令反汇编/事件发射 |

## 3. 关键数据结构

### 3.1 CPU 状态

```c
typedef struct {
    uint32_t x[32];        // x0 恒 0（写回处统一 if (rd != 0)）
    uint32_t pc;
    uint8_t  priv;         // 0=U, 1=S, 3=M
    csr_t    csr;          // ★ 唯一的一份 CSR 存储（含 mcycle/minstret）
    uint32_t cur_instr;    // 当前指令编码（供调试层）
    // LR/SC reservation
    bool     lr_valid;
    uint32_t lr_addr;      // 必须是物理地址
} cpu_t;
```

> **v2.0 的错误**：`cpu_t` 里另有 `cycles`/`instret` 两个 uint64，与 `csr_t.mcycle`/`minstret` 形成双份存储。所有计数器读写必须只走 `csr.mcycle`/`csr.minstret`。

```c
typedef struct {
    // ── M 模式 ──
    uint32_t mstatus;
    uint32_t mstatush;     // ★ RV32 必须有（SBE/MBE/GVA 等高位）
    uint32_t mtvec, mepc, mcause, mtval, mscratch;
    uint32_t mie, mip, mideleg, medeleg;
    uint32_t misa, mhartid, mvendorid, marchid, mimpid;
    uint32_t mcounteren, mcountinhibit;
    uint64_t mcycle, minstret;   // 64 位，**可写**
    uint32_t mnstatus;           // 0x744，见 §4.6
    // ── PMP ──
    uint32_t pmpcfg[4];          // 0x3A0-0x3A3（RV32 每字节一个配置）
    uint32_t pmpaddr[16];        // 0x3B0-0x3BF
    // ── 真正独立的 S 模式 CSR（其余是视图，见 §3.2） ──
    uint32_t stvec, sepc, scause, stval;
    uint32_t satp, sscratch, scounteren;
} csr_t;
```

### 3.2 CSR：**只有一份存储，S 模式是视图**

这是 v1.0 最严重的结构错误。规范原文：

> `sstatus` 是 `mstatus` 的**子集**——"reading or writing any field in `sstatus` is equivalent to reading or writing the homonymous field in `mstatus`"。
> `sie`/`sip` 是 `mie`/`mip` 经 `mideleg` 掩码后的**视图**——未委派的位读 0、写忽略。

```c
typedef struct {
    // ── 一份物理存储 ──
    uint32_t mstatus;      // 位定义见 §3.3
    uint32_t mtvec, mepc, mcause, mtval, mscratch;
    uint32_t mie, mip, mideleg, medeleg;
    uint32_t misa, mhartid, mvendorid, marchid, mimpid;
    uint32_t mcounteren, mcountinhibit;
    uint64_t mcycle, minstret;   // 64 位，**可写**
    // ── PMP ──
    uint32_t pmpcfg[4], pmpaddr[16];
    // ── mnstatus（未实现扩展时读写不报错） ──
    uint32_t mnstatus;
    // ── 真正独立的 S 模式 CSR ──
    uint32_t stvec, sepc, scause, stval;
    uint32_t satp, sscratch, scounteren;
} csr_t;
```

**S 模式 CSR 的读写必须走掩码函数**，不能各存一份：

```c
// sstatus 读写：映射到 mstatus 的同名字段
// 掩码 = SIE(1) | SPIE(5) | SPP(8) | FS(14:13) | XS(16:15) | SUM(18) | MXR(19) | SD(31)
//   bit1  0x00000002
//   bit5  0x00000020
//   bit8  0x00000100
//   bit13 0x00002000, bit14 0x00004000
//   bit15 0x00008000, bit16 0x00010000
//   bit18 0x00040000
//   bit19 0x00080000
//   bit31 0x80000000
// 合计 = 0x800DE122
// 明确排除：bit0(UIE)/bit4(UPIE) 是 N 扩展，本项目不做 → RO 0；
//           bit6(UBE) 本项目不实现统一字节序 → RO 0，故不在掩码内
#define SSTATUS_MASK  0x800DE122u
uint32_t csr_read_sstatus(csr_t *c) { return c->mstatus & SSTATUS_MASK; }
void csr_write_sstatus(csr_t *c, uint32_t v) {
    c->mstatus = (c->mstatus & ~SSTATUS_MASK) | (v & SSTATUS_MASK);
}

// sie / sip：mideleg 掩码后的视图
uint32_t csr_read_sie(csr_t *c) { return c->mie & c->mideleg; }
void csr_write_sie(csr_t *c, uint32_t v) {
    uint32_t mask = c->mideleg;            // 只有委派出去的位可写
    c->mie = (c->mie & ~mask) | (v & mask);
}
```

### 3.3 `mstatus` 位定义（**按 v20260120 逐位核对过**）

| 位 | 名称 | 本项目取值 | 说明 |
|---|---|---|---|
| 0 | UIE | RO 0 | N 扩展，不做 |
| **1** | **SIE** | 可写 | S 模式中断使能 |
| 2 | — | 保留 | |
| **3** | **MIE** | 可写 | M 模式中断使能 |
| 4 | UPIE | RO 0 | N 扩展，不做 |
| **5** | **SPIE** | 可写 | S 模式上一中断使能 |
| 6 | UBE | RO 0 | 统一字节序，不实现 |
| **7** | **MPIE** | 可写 | M 模式上一中断使能 |
| **8** | **SPP** | 可写 | S 模式上一特权级（0=U, 1=S） |
| 9-10 | VS[1:0] | RO 0 | V 扩展，不做 |
| **12:11** | **MPP[1:0]** | 可写 | 上一特权级（0=U, 1=S, 3=M）**← 掩码 0x1800** |
| **14:13** | **FS[1:0]** | RO 0 | 无 F 实现 |
| 16:15 | XS[1:0] | RO 0 | 未实现 |
| **17** | **MPRV** | 可写 | 访存用 MPP 而非当前特权级 **← 掩码 0x20000** |
| **18** | **SUM** | 可写 | 允许 S 模式访问 U 页（仅数据，取指永远不行） |
| **19** | **MXR** | 可写 | 把可执行页当可读 |
| 20 | TVM | RO 0 | 未实现 |
| 21 | TW | RO 0 | 未实现 |
| 22 | TSR | RO 0 | 未实现 |
| 23 | SPELP | RO 0 | 未实现 |
| 24-31 | SD 等 | RO 0 | |

**必须与 riscv-tests 对齐的两个掩码**（`env/encoding.h` 里就是这么定义的）：
```c
#define MSTATUS_MPP   0x00001800u   // bit 12:11
#define MSTATUS_MPRV  0x00020000u   // bit 17
#define MSTATUS_SIE   0x00000002u   // bit 1
#define MSTATUS_MIE   0x00000008u   // bit 3
#define MSTATUS_SPP   0x00000100u   // bit 8
#define MSTATUS_MPIE  0x00000080u   // bit 7
#define MSTATUS_SPIE  0x00000020u   // bit 5
#define MSTATUS_SUM   0x00040000u   // bit 18
#define MSTATUS_MXR   0x00080000u   // bit 19
```

> **v2.0 的错误**：曾把 SIE 写为 bit0、MIE 写为 bit1、MPP 写为 bit4/5、MPRV 在 bit3 与 bit17 各写一次。照那张表实现会让 `dirty.S`（`MSTATUS_MPP=0x1800`、`MSTATUS_MPRV=0x20000`）与 Gate 1 的 U 模式入口全部失败。

### 3.4 总线：**必须先判 RAM**

**v2.0 曾用 256 槽查表，已废弃**。两个理由：
1. 查表伪码里的门限 `if (addr >= 0x10000000u && addr < 0x80000000u) return 0;` 会把 **UART 自己的基址 `0x1000_0000`** 判成"未映射"，UART 永远不可访问
2. 高位折叠（`&0xFF`）会让 `0x9000_0000` 折叠到槽 0（UART），产生别名

**改为设备区间线性遍历**（设备只有 4 个，成本可忽略，且无别名问题）：

```c
typedef struct {
    uint32_t base, size;
    const char *name;
    int (*access)(void *dev, uint32_t off, int len, bool is_write,
                  uint32_t *val);
    void *dev;
} mmio_region_t;

static mmio_region_t devs[] = {
    { 0x00100000u, 0x1000,     "syscon", syscon_access, &syscon },
    { 0x02000000u, 0x10000,    "clint",  clint_access,  &clint  },
    { 0x0C000000u, 0x400000,   "plic",   plic_access,   &plic   },
    { 0x10000000u, 0x100,      "uart",   uart_access,   &uart   },
};
#define NDEVS (sizeof(devs)/sizeof(devs[0]))

static int bus_access(uint32_t addr, int len, bool is_write, uint32_t *val) {
    // ★ 不变量 1：RAM 优先。
    //   0x8000_0000>>20 & 0xFF == 0（若先查表会撞 UART）
    //   0x8200_0000>>20 & 0xFF == 32（若先查表会撞 CLINT）
    if (addr >= RAM_BASE && (uint64_t)addr + len <= (uint64_t)RAM_BASE + RAM_SIZE) {
        return ram_access(addr - RAM_BASE, len, is_write, val);
    }
    // ★ 不变量 2：逐设备判断区间，绝不按高位折叠
    for (size_t i = 0; i < NDEVS; i++) {
        if (addr >= devs[i].base &&
            (uint64_t)addr + len <= (uint64_t)devs[i].base + devs[i].size) {
            return devs[i].access(devs[i].dev, addr - devs[i].base, len, is_write, val);
        }
    }
    return 0;   // 未映射 → 上层决定抛 access fault 还是返回 0
}
```

**必须有的定向测试**：对整个 RAM 区间做写读回环，确认没有任何一段被路由到设备。

**为什么不用 256 槽查表（历史说明，避免再犯）**

若按 `(addr>>20)&0xFF` 取槽号：

| 设备 | 基址 | 槽号 |
|---|---|---|
| UART | `0x1000_0000` | 0 |
| CLINT | `0x0200_0000` | 32 |
| PLIC | `0x0C00_0000` | 192 |
| syscon | `0x0010_0000` | 1 |
| **RAM** | `0x8000_0000` | **0（撞 UART）** |
| **RAM** | `0x8200_0000` | **32（撞 CLINT）** |

设备之间不冲突，但**与 RAM 冲突**；且 `&0xFF` 折叠会让 `0x9000_0000` 这类地址产生别名。故改用区间遍历。

### 3.5 调试事件（每指令 5 个阶段）

**修正 v1.0 的错误**：`stage`（单值）+ `valid`（单值）表达不了阶段视图。Ripes 的做法是"每拍 + 5 段有效位"，而解释器里没有"拍"的概念，所以改为**每条指令发 5 个逻辑阶段事件**：

```c
typedef struct {
    uint32_t pc;
    uint32_t instr;        // 指令编码，前端自行反汇编
    uint8_t  stage;        // 0=取指 1=译码 2=执行 3=访存 4=写回
    uint8_t  valid;        // 该阶段是否发生（如无访存则 stage 3 无效）
    uint64_t cycle;
    uint32_t rd, rs1, rs2; // 供前端高亮（capstone 无 regs_access，需自备表）
    uint32_t csr_changed;  // CSR 变化掩码
} stage_event_t;
```

> **必须说明**：这是**逻辑阶段**，不是硬件并行。演示时若被问"你的流水线呢"，答案应是"本项目是解释执行，阶段视图用于教学展示，不是硬件流水线"。

## 4. CSR 全表（**这是 v1.0 最大的漏项**）

| 地址 | 名称 | 说明 | 来源 |
|---|---|---|---|
| 0x300 | `mstatus` | 见 §3.3 | Priv Ch1 |
| 0x301 | `misa` | **`0x40141101`**（MXL=1<<30 \| U \| S \| M \| I \| A）；WARL，写只读位忽略，不 trap | Priv Ch1 |
| 0x302/0x303 | `medeleg`/`mideleg` | 委派 | Priv Ch1 |
| 0x304/0x344 | `mie`/`mip` | 中断使能/挂起 | Priv Ch1 |
| 0x305 | `mtvec` | 低 2 位 MODE：0=Direct, 1=Vectored；2/3 保留 → WARL 归一 | Priv Ch2 |
| 0x306 | **`mcounteren`** | v1.0 漏了。`rv32mi-p-csr` 会写它 | Priv Ch2 |
| 0x310 | `mstatush` | **RV32 必须有**（放 SBE/MBE 等高位） | Priv Ch1 |
| 0x320 | **`mcountinhibit`** | v1.0 漏了。`instret_overflow.S` 会探测 | Priv Ch2 |
| 0x340/0x341/0x342/0x343 | `mscratch`/`mepc`/`mcause`/`mtval` | trap 相关 | Priv Ch2 |
| 0xB00/0xB02 | `mcycle`/`minstret` | **64 位可写** | Priv Ch2 |
| 0xB80/0xB82 | **`mcycleh`/`minstreth`** | v1.0 漏了。RV32 必须有 | Priv Ch2 |
| 0xF11/0xF12/0xF13/0xF14 | `mvendorid`/`marchid`/`mimpid`/`mhartid` | **Linux M 模式启动直接读**，缺失即崩 | Priv Ch2 |
| 0x744 | **`mnstatus`** | v1.0 漏了。riscv-test-env 的 reset 会写它；未实现扩展时读写不报错 | Priv Ch1 |
| 0x100/0x104/0x105 | `sstatus`/`sie`/`stvec` | **视图/独立混合**，见 §3.2 | Priv Ch11 |
| 0x106/0x140/0x141/0x142/0x143 | `scounteren`/`sscratch`/`sepc`/`scause`/`stval` | | Priv Ch11 |
| 0x144 | `sip` | v1.0 漏了 | Priv Ch11 |
| 0x180 | `satp` | RV32：MODE=bit31、ASID=30:22、PPN=21:0 | Priv Ch11 |
| 0xC00/0xC01/0xC02 | `cycle`/`time`/`instret` | 只读影子 | Priv Ch2 |
| 0xC80/0xC82 | `cycleh`/`instreth` | RV32 只读高半 | Priv Ch2 |
| **0x3A0-0x3A3** | **`pmpcfg0`-`pmpcfg3`** | **v2.0 漏了**。RV32 上 `pmpcfg0` 的 4 个字节各对应 cfg0..cfg3；`r/w` 合法，强制不生效 | Priv Ch3.6 |
| **0x3B0-0x3BF** | **`pmpaddr0`-`pmpaddr15`** | **v2.0 漏了**。`riscv-test-env` 的 `INIT_PMP` 会写 `pmpaddr0=0x7FFF_FFFF`、`pmpcfg0=0x1F`（NAPOT+RWX），**即使不实现强制也必须能回读** | Priv Ch3.6 |

**`mstatush`（RV32 特有，0x310）位定义**：

| 位 | 名称 | 本项目 |
|---|---|---|
| 4 | SBE | RO 0（不实现大端） |
| 5 | MBE | RO 0 |
| 6 | GVA | RO 0（未实现 H） |
| 其余 | — | RO 0 |

**`misa` 必须显式设值的原因**：`rv64si/csr.S` 用 `misa.U`(bit20) 决定是否执行 U 模式那组检查（`beqz a0, finish` 跳过），`ma_fetch.S` 用 `misa.C` 决定跳过 C 子测试。若 `misa.U=0`，测试会"通过"但什么都没验证。

### 4.1 `mip` 的可写性（**P0，v2.0 缺失**）

| 位 | 名称 | 可写性 | 驱动方 |
|---|---|---|---|
| 1 | SSIP | **可写** | `sip.SSIP` 是它的视图；`rv32si-p-wfi` 依赖 |
| 3 | MSIP | **可写** | 软件写 |
| 5 | STIP | **可写** | 软件写 |
| 7 | MTIP | **只读** | CLINT 的 `mtime >= mtimecmp` |
| 9 | SEIP | 平台定义 | 本实现：PLIC 有 pending 且 enable 时置位；`mip.SEIP` 只读，`sip.SEIP` 是只读视图 |
| 11 | MEIP | **只读** | PLIC 驱动 |

`mie` 的对应位均可写（但 `mideleg` 为 0 的位在 `sie` 视图中读 0）。

### 4.2 `mcounteren` / `scounteren` 规则（**P0**）

| 位 | 名称 | 控制 |
|---|---|---|
| 1 | TM | 允许下一特权级读 `time` |
| 0 | CY | 允许下一特权级读 `cycle` |
| 2 | IR | 允许下一特权级读 `instret` |

访问判定链：
```
M 模式读计数器：永远允许
S 模式读：需 mcounteren.X == 1，否则 illegal
U 模式读：需 mcounteren.X == 1 且 scounteren.X == 1，否则 illegal
写 cycle/instret/time（只读影子）：任何模式都 illegal
```
`mcountinhibit`：`CY`(bit0) 为 1 时 `mcycle` 停止自增，`IR`(bit2) 为 1 时 `minstret` 停止自增。

> 路线 B 的 S 模式 Linux 要读 `rdtime`，**必须把 `mcounteren.TM` 置 1**，否则内核早期 `illegal instruction`。

### 4.3 `MPRV` / `SUM` / `MXR` / `satp` 的语义（**P0，`dirty.S` 的必要条件**）

| 机制 | 精确语义 |
|---|---|
| **`satp`** | **对 M 模式取指无效**（M 模式永远走物理地址取指） |
| **`MPRV=0`** | M 模式访存不做地址翻译 |
| **`MPRV=1`** | M 模式访存按 `MPP` 指定的特权级翻译并做权限检查（`MPP=0` 按 U 模式、`MPP=1` 按 S 模式） |
| **`MPRV` 不影响取指** | 无论 `MPRV` 如何，取指始终按当前特权级 |
| **`SUM`** | 只放宽 **S 模式**（含 `MPRV=1 && MPP=S` 的情况）对 U 页的**数据**访问；**取指永不放宽** |
| **`MXR`** | 只影响 **load**：把 `X=1,R=0` 的页当作可读；不影响 store 与取指 |

`dirty.S` 的完整依赖链：`csrw satp` → `sfence.vma` → 设 `mstatus.MPP=S`、`MPRV=1` → 以 M 模式访问被翻译的地址 → 校验 PTE 的 A/D 被置位。

### 4.4 PLIC 规格（**P0，Gate 6 必需**）

| 项 | 值 |
|---|---|
| 基址 | `0x0C00_0000`，大小 4 MB（覆盖到 `0x0C3F_FFFF`） |
| **UART 中断源号** | **10**（dtb 里 `interrupts = <10>`） |
| priority | `0x0000_0000 + 4*id`（id=1..1023） |
| pending | `0x0000_1000 + 4*(id/32)`（只读） |
| enable（每 context 一组） | `0x0000_2000 + 0x80*ctx + 4*(id/32)` |
| threshold（每 context） | `0x0000_200000 + 0x1000*ctx` |
| **claim/complete**（每 context） | **`0x0020_0000 + 0x1000*ctx`**（读写同一地址：读=claim，写=complete） |

本实现只需 **单 context（ctx=0，hart0 的 M 模式）**。

中断链路：
```
UART 收到字节 → RBR 非空 → PLIC pending[10]=1
  若 enable[10] 且 priority[10] > threshold
    → 置 mip.MEIP（M 模式）或 mip.SEIP（若委派）
UART 中断处理：读 RBR 清源 → 写 claim/complete 地址 complete
```

> **v2.0 的错误**：只写了"PLIC 4 MB"，没有 `claim/complete` 的偏移。`0x0C20_0000` 落在基址 + 2 MB 处，**若设备区间只注册前 1 MB 就取不到中断号**。现已用区间遍历（`base=0x0C000000, size=0x400000`），覆盖无遗漏。

## 5. Sv32 规格（**一页说清，v1.0 缺**）

### 5.1 `satp`（RV32）

```
bit 31      : MODE   (0=Bare, 1=Sv32)
bit 30:22   : ASID   (9 位)
bit 21:0    : PPN    (22 位)  -> 根页表物理地址 = PPN << 12
```
- 写入不支持的 MODE ⇒ **整条写无效**（不是部分写）

### 5.2 PTE（4 字节）

```
31:10 : PPN[1:0]（物理页号）
 9:8  : RSW
  7   : D
  6   : A
  5   : G
  4   : U
  3   : X
  2   : W
  1   : R
  0   : V
```
- `R=0 && W=1` ⇒ 保留编码 ⇒ page fault
- 非叶 PTE 的 D/A/U 必须为 0（本实现不强制，但不得因它们非零而误判）

### 5.3 两级遍历（9 步算法）

```
1. satp.MODE == 0（Bare）⇒ 物理地址 = 虚拟地址，直接返回
2. 取 a = satp.PPN * 4096
3. i = 1（根层）
4. pte = *(uint32_t*)(a + va.vpn[i] * 4)
5. 若 pte.V == 0 或 (pte.R==0 && pte.W==1) ⇒ page fault
6. 叶判定：pte.R==1 || pte.X==1
   - 若叶：
     a) i > 0 且 pte.ppn[i-1:0] != 0 ⇒ misaligned superpage ⇒ page fault
     b) 按 U/SUM/MXR 检查权限
     c) 若 A==0 → 置 A（本实现硬件置位）
     d) 若是写且 D==0 → 置 D
     e) 物理地址拼接（**按超页大小分别处理**）：
        - 4 KiB 页（i=0）：pa = (pte.ppn << 12) | (va & 0x00000FFF)
        - 4 MiB 超页（i=1）：pa = (pte.ppn[1] << 22) | (va & 0x003FFFFF)
        ★ 注意：pte.ppn 是 22 位，`pte.ppn << 12` 在 32 位下会溢出丢高位；
          物理地址在 RV32 上是 34 位（PMA 决定实际可用位数），
          实现里用 uint64_t 或分两次移位拼接。
     f) 返回
   - 若非叶：a = pte.ppn * 4096；i--；回到 4
7. i < 0 ⇒ page fault
```
- **超页检查**：4 MiB 超页要求 `pte.ppn[0] == 0`，否则 page fault（`rv32si-p-dirty` 测这条）
- **权限顺序**：U 位（含 SUM）→ R/W/X → page fault
- **`sfence.vma`**：本实现无 TLB，可作 NOP，但必须合法译码；U 模式执行 ⇒ illegal
- **S 模式不可执行 U 页**：即使 `SUM=1` 也只放宽数据访问，取指永远不行

## 6. 复位状态（**v1.0 完全没写，必须定死**）

| 项 | 初值 |
|---|---|
| 特权级 | M |
| `pc` | `0x8000_0000`（或 ELF entry） |
| `mstatus` | **全 0**（MIE=0, MPIE=0, MPP=0, MPRV=0, SIE=0, SPIE=0, SPP=0） |
| `mstatus.MPRV` | 0 |
| `misa` | `0x40141101`（最大支持集） |
| `mhartid` | 0 |
| `mvendorid`/`marchid`/`mimpid` | 0（只读 0 合法） |
| `mcounteren`/`mcountinhibit`/`mstatush`/`mnstatus` | 0 |
| `mcause` | 0 |
| `mtvec`/`mepc`/`mtval`/`mie`/`mip` | 0（规范为 UNSPECIFIED，本实现自定） |
| `medeleg`/`mideleg` | **0** |
| `satp` | 0（Bare） |
| `pmpcfg0..3` | 0（`A=0,L=0`，不实现强制） |
| `pmpaddr0..15` | 0 |
| `stvec`/`sepc`/`scause`/`stval`/`sscratch`/`scounteren` | 0 |
| load reservation | **无效**（`lr_valid=0`） |
| **`mtime`** | 0 |
| **`mtimecmp`** | **全 1（`0xFFFF_FFFF_FFFF_FFFF`）** ← **关键** |

> **`mtimecmp` 必须复位成全 1**：若为 0，则复位后 `mtime >= mtimecmp` 立刻成立 → `MTIP` 持续置位 → **Linux 启动瞬间进入中断风暴**，表现为卡死在第一条指令。真实硬件（以及 QEMU）的复位值都是全 1。
>
> 规范对 `mtvec`/`mepc`/`mtval`/`mie`/`mip` 等说 "All other hart state is UNSPECIFIED"，**必须自己定并写死**，否则 WASM 前端与回归不可复现。

## 7. 关键技术难点与对策

### 7.1 CSR 与异常/中断的交互（最难）

**具体坑**：
1. `mstatus` 的 `MIE/MPIE/MPP` 栈式保存/恢复
2. `mtvec` 低 2 位；Vectored 下**异常仍跳 BASE**，只有中断跳 `BASE+4*cause`
3. **`mepc` = 触发 trap 的指令地址，所有 trap 一律如此（含 ecall）。`+4` 必须由 handler 自己做——硬件不能替它加。**（v1.0 写错这条，会导致 `dirty.S` 直接跑飞）
4. **`mret`/`sret` 不是"反向恢复"**：
   ```
   xIE ← xPIE
   xPIE ← 1        ← 不是恢复旧值
   xPP ← U
   若 y ≠ M: MPRV ← 0
   sret 另加: SPP ← 0
   ```
5. `mcause` 最高位区分中断/异常
6. `mtval` 策略见 FR-4.6
7. 非法 CSR 访问（地址无效或特权不足）→ illegal instruction（cause 2）；写只读 CSR 也 → illegal

**对策**：位域操作全部封装成宏；先过 `rv32mi-p-csr`；用 spike 逐条比对中间值。

### 7.2 取指边界

- 4 字节对齐，可能跨 4 KiB 页
- `jalr` 必须清 bit0
- 分支目标 misaligned → `inst-addr-misaligned`（由**控制流指令**触发，优先级低于 illegal/ecall，**且 rd 不得写回**）
- 无 C 扩展 ⇒ PC 只需 4 字节对齐（简化）

### 7.3 misaligned 数据访问

**必须硬件支持**（`rv32ui-p-ma_data` 没有 trap handler）：
- 总线层分解为字节/半字访问
- **例外**：AMO 不拆字 ⇒ misaligned AMO 抛 cause 6

### 7.4 系统边界闭环

- ELF `PT_LOAD` 装载 + `p_memsz` 清零 bss
- 初始寄存器：`a0=hartid`、`a1=dtb 物理地址`、`sp`、`satp=0`
- `tohost` 从**符号表**读，监视**物理地址**
- UART 的 THR + LSR.THRE（否则 Linux 8250 驱动卡住）
- **UART 接收中断 + PLIC**（否则进不了 shell）
- CLINT 偏移：`mtimecmp@+0x4000+8*hart`、`mtime@+0xBFF8`
- `mtime` 推进：`mtime += cycles / DIV`，使 guest 主频匹配 dtb 的 1 MHz

### 7.5 退出机制（v1.0 有错）

| 场景 | 触发 | 判定点 |
|---|---|---|
| riscv-tests (`-p`) | `ecall` → 测试 trap_vector → 写 `tohost` | **监视 `tohost` 的 store**：`1`=PASS，奇数>1=FAIL |
| Linux S 模式 | SBI SRST（EID `0x53525354`） | 拦截后停止 |
| Linux M 模式 | `wfi` 死循环 | **不能用"连续 N 次相同 PC"**（对 `wfi; j .` 无效）。改为：PC 与上次相同**或**形成 2–3 条环路，且 `mtimecmp` 不变 |
| 兜底 | `max_cycles` | 超时 |

**`a0` 不是恒为 0**：`RVTEST_FAIL` 写 `a0 = (TESTNUM<<1)|1`。但仅拦截 `ecall` 读 `a0` 仍不可靠，正确做法是走 trap + 监视 `tohost`。

**QEMU 对照（必须传同一份 dtb）**：
```bash
# QEMU 8.2.2 的 -cpu rv32 的 misa = 0（无 M/A），跑不了 RV32IMA，必须用 sifive-e34
qemu-system-riscv32 -M virt -cpu sifive-e34 -m 64M -bios none \
  -kernel third_party/linux-image/Image -dtb dts/minimal.dtb -nographic
```
**验收降级为"语义一致"**（串口输出的行集合一致），不要求逐字节——QEMU virt 的硬件细节与自写 dtb 不可能完全对齐。

## 12. 已知限制

1. 不做 C/F/D/B/V 扩展
2. 不做 JIT（30 MIPS 解释执行）
3. 单 hart
4. 迷你内核无文件系统
5. 不实现 Debug Spec（自定义协议）
6. 不做 ACT4 认证
7. **阶段视图是逻辑阶段，不是硬件流水线**——演示被问"你的流水线呢"时，答案应是"解释执行，阶段视图用于教学展示"
8. **不做 `-v` 测试变体**（需 newlib，且该规则用 `-nostdlib` 且不加 `--specs`，picolibc 救不了）
9. **不自写 NOMMU 用户程序**（`ld` 无 `-Wl,-elf2flt`，工具链无 elf2flt）
10. **PMP 不做强制**（仅寄存器可读写）。**注意：`rv32mi-p-pmpaddr` 在 G=0 时直接跳 pass，对 PMP 的验证强度为零——演示不能声称"PMP 已验证"**
11. **不做与 spike 的差分测试**（spike 未装，需 boost）。正确性靠 riscv-tests 82 项 + 自写定向断言
12. **git 推送当前走 GitHub API**（代理节点失效，git 的 HTTPS/SSH 均不通）。修好代理后可恢复常规 `git push`
13. **不做 QEMU 逐字节对照**，只做语义一致（行集合）——QEMU virt 的硬件细节与自写 dtb 不可能完全对齐
