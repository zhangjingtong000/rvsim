# 需求文档 · RISC-V 模拟器与迷你内核

**版本**：v2.0（2026-10-26 修订）
**状态**：待二次审核
**v1.0 → v2.0 的主要修订**：重排验收门（Gate 1 即需 U 模式）、补全 CSR 清单、定死设备图与 dtb 策略、修正 `mepc`/`mret` 规范错误、放弃 `-v` 变体与 elf2flt 路线、修正 QEMU 对照方案、标注所有数字口径。

---

## 1. 项目概述

### 1.1 定位

> 从零实现一个 RISC-V 指令集模拟器，能通过 riscv-tests 的 RV32IMA 一致性测试、能启动 Linux 内核，并在其上运行一个自制的迷你内核，附带可视化调试界面。

### 1.2 规范基线（**开工前必须先钉死**）

| 项 | 取值 |
|---|---|
| 非特权指令集 | I 2.1 + M 2.0 + A 2.1 + Zicsr 2.0 + Zifencei 2.0 |
| 特权级架构 | 1.12 基线（**不启用** Smdbltrp / Smnmi / Zicfilp / Zicfiss / Sstc） |
| hart 数 | 单 hart（`mhartid = 0`） |
| `misa` | **`0x4014_1101`** = `MXL=1<<30 \| U(1<<20) \| S(1<<18) \| M(1<<12) \| I(1<<8) \| A(1<<0)`；C=0 |
| PMP | **不实现强制**（PMP CSR 可读写，但不做访问拦截）；NAPOT 全空间匹配无论是否实现都必须正确 |
| Sv32 | 实现，硬件置 A/D 位（不走 Svade） |
| 未实现字段 | `mstatus` 中未实现的扩展字段一律 **read-only 0** |
| 不启用 | C / F / D / B / V / H 扩展 |

> `misa` 必须显式设成上面这个值。**原因**：`rv64si/csr.S` 用 `misa.U` 决定是否执行 U 模式那组检查，`ma_fetch.S` 用 `misa.C` 决定跳过 C 子测试。若 `misa.U=0`，测试会静默跳过检查后报 PASS——那种 82/82 是假的。

### 1.3 "从零"的边界

| 本项目自研 | 被测负载（不要求自研） |
|---|---|
| RV32IMA 译码与执行 | Linux 内核镜像 |
| CSR 与特权级（M/S/U） | OpenSBI 固件（若启用路线 B） |
| 异常与中断 | rootfs / BusyBox |
| MMU（Sv32） | riscv-tests 的测试用例 |
| MMIO 总线与设备模型 | 测试用的基准程序 |
| dtb 的**内容**（dts） | dtc 工具 |
| ELF 加载器、测试 harness | — |
| 迷你内核 | — |
| 调试器与可视化前端 | — |

**支撑这个边界的硬证据**（演示可展示）：

1. **同 dtb 对照**：自写 dtb + 同一份 `Image`，在本模拟器与 QEMU（`-cpu sifive-e34 -m 64M -dtb <同一份 dtb>`）上运行，**串口输出的语义一致**（行集合一致；逐字节一致不作为验收项，见 §5 Gate 6）
2. **固件可替换**：启用路线 B 时，把 OpenSBI 换成自写的最小 SBI，内核照样启动
3. **路线合法**：RV32 + NOMMU + M 模式是上游支持的配置（buildroot `qemu_riscv32_nommu_virt_defconfig`，内核 6.18.7）；但**注意**：主线已不再维护 RV32 的 Sv32 运行时实现（`arch/riscv/mm/pgtable-32.c` 已删），所以说的是"主线不维护 RV32 的 MMU 路径"，不是"配置上不可能"

### 1.4 设备图（**定死，不得再出现第二套**）

采用 **QEMU virt 布局**，理由是只有这样才能让「同一份 dtb + 同一份 Image」在 QEMU 和本模拟器上对照。

| 设备 | 基址 | 大小 | 说明 |
|---|---|---|---|
| CLINT | `0x0200_0000` | 64 KB | `msip[hart]@+0x0000`、`mtimecmp[hart]@+0x4000+8*hart`、`mtime@+0xBFF8`（64 位，RV32 分两次 32 位读） |
| PLIC | `0x0C00_0000` | 4 MB | 最小实现：单 context（ctx=0）。**中断源 10 = UART0**（与 QEMU virt 一致）；`riscv,ndev = 31`（必须 > 10）。寄存器：`priority@0x0+4*id`、`enable@0x2000+0x80*ctx+4*(id/32)`、`threshold@0x20_0000+0x1000*ctx`、`claim/complete@0x20_0000+0x1000*ctx`（同址读写） |
| UART (16550A) | `0x1000_0000` | 256 B | THR/RBR/DLL/IER/FCR/LCR/MCR/LSR/SCR；**`compatible = "ns16550a"`**（不是 `hvc`，也不是 `ns16850`） |
| syscon (poweroff/reboot) | `0x0010_0000` | 4 KB | QEMU virt 的 test 设备；poweroff 写 `0x5555`，reboot 写 `0x7777` |
| RAM | `0x8000_0000` | 64 MB | Linux 镜像需 4 MB 对齐（RV32 PMD 边界） |

**⚠️ 中断号必须写死**：QEMU virt 的 UART0 固定接 PLIC **source 10**。若自写 dtb 写成别的号（或 `riscv,ndev` < 10），本模拟器能跑，但 QEMU 侧串口中断永远不触发——"同一份 dtb 两边对照"这条验收直接崩。

### 1.5 dts 必备属性（**缺一项就启动不了**）

按现有信息写 dts，`dtc` 会报 `phandle_references` 错误。必须包含：

| 节点 | 必备属性 |
|---|---|
| `/chosen` | **`stdout-path = "/soc/serial@10000000"`**（没它 Linux 8250 不输出 console） |
| `/cpus/cpu@0` | `riscv,isa = "rv32ima_zicsr_zifencei"`（写成 `rv32imac` 会被内核判 unsupported）、`mmu-type = "riscv,none"`、`reg = <0>` |
| `/cpus` | **`timebase-frequency = <0xF4240>`**（1 MHz，须与模拟器 `mtime` 推进速度一致） |
| `/memory@80000000` | `device_type = "memory"`、`reg = <0x80000000 0x4000000>` |
| `cpuintc`（中断控制器） | `compatible = "riscv,cpu-intc"`、`#interrupt-cells = <1>`、`interrupt-controller`；**必须带 label**，供 phandle 引用 |
| `plic` | `compatible = "riscv,plic0"`、`riscv,ndev = <31>`、`#interrupt-cells = <1>`、`interrupt-controller`、**`interrupts-extended = <&cpuintc 11>`**（MEIP）、`reg = <0x0C000000 0x400000>` |
| `clint` | `compatible = "riscv,clint0"`、**`interrupts-extended = <&cpuintc 3 &cpuintc 7>`**（MSIP/MTIP 两条，缺则 `clint_timer_init_dt()` probe 失败） |
| `serial@10000000` | `compatible = "ns16550a"`、`clock-frequency = <3686400>`、`reg-shift = <0>`、**`interrupts = <10>`** |

**实测记录**：按不完整信息写的 dts，`dtc` 报 4 条 `phandle_references` 错误；补全上表后才编过（产物 1527 字节，头部 `d0 0d fe ed`）。

**CLINT 的 dtb 必须写全 `interrupts-extended = <&cpuintc 3 &cpuintc 7>`**（MSIP=3 与 MTIP=7）。缺失则 `clint_timer_init_dt()` probe 失败，Linux 卡在时间初始化。

**UART 的 dtb 必须带 `interrupts`**（用于接收中断）。原始 mini-rv32ima 的 dts 里 uart **没有** interrupts 属性，那是"只出无入"的 demo，不能用于 Gate 6 的交互验收。

## 2. 路线选择

**已定：路线 A（M 模式直启）为主，路线 B（OpenSBI + S 模式）为加分。**

| 路线 | 说明 | 何时做 |
|---|---|---|
| **A（主线）** | Linux 以 M 模式直接启动（`RISCV_M_MODE` 在 `!MMU` 时默认 `y`）。模拟器加载 `Image` → `a0=hartid`、`a1=dtb 地址`、`satp=0` → 跳入口 | Gate 6 |
| **B（加分）** | 加载 OpenSBI（RV32 可编，272 KB）→ 建立 SBI → 移交 S 模式内核 | 可选，Gate 7 之后 |

## 3. 功能需求

优先级：**P0** = 不做则项目不成立；**P1** = 核心交付；**P2** = 加分。

### FR-1 指令集（P0）

| 编号 | 需求 | 验收 |
|---|---|---|
| FR-1.1 | RV32I 全部 **40 条**（不是 37 条）基础指令 | Gate 2：`rv32ui-p-*` 42/42 |
| FR-1.2 | RV32M（8 条乘除），`div`/`rem` 的除零与溢出返回值 | Gate 3：`rv32um-p-*` 8/8 |
| FR-1.3 | RV32A：`lr`/`sc` + AMO，`aq`/`rl` 位 | Gate 3：`rv32ua-p-*` 10/10 |
| FR-1.4 | `lr` 的 `aq=rl=1` 是保留编码（可实现为 illegal 或忽略） | 定向测试 |
| FR-1.5 | `sc` 失败返回 **1**；**任何 trap 都清 load reservation** | 定向测试 |
| FR-1.6 | AMO 不拆字 ⇒ misaligned AMO 抛 store/AMO misaligned（cause 6） | `rv32mi-p-ma_addr` |
| FR-1.7 | Zicsr 6 条指令 | Gate 4 |
| FR-1.8 | Zifencei 的 `fence.i` | Gate 2 起 |
| FR-1.9 | **`sfence.vma`** | Gate 5（`rv32si-p-dirty` 第一条就是它） |
| FR-1.10 | **`wfi`**：在 `SIE=0` 时**不阻塞**（实现为 NOP 合法） | Gate 5（`rv32si-p-wfi`） |
| FR-1.11 | `fence` / `fence.i` 的语义 | 见下方说明 |

**`fence` / `fence.i` 的实现前提（必须写进论文）**：
- 单 hart、严格顺序执行、无 I-cache/D-cache、取指直接读内存 ⇒ 可实现为 NOP
- **保留编码（`fm≠0`、`rd/rs1≠0`）不得报 illegal**，按普通 fence 处理
- 一旦引入译码缓存或块缓存，`fence.i` 必须失效之

**明确不做**：C / F / D / B / V。

### FR-2 内存与外设（P0）

| 编号 | 需求 | 验收 |
|---|---|---|
| FR-2.1 | RAM 基址 `0x8000_0000`，容量 64 MB（可配） | Linux 启动 |
| FR-2.2 | CLINT：`msip` / `mtimecmp` / `mtime`，偏移见 §1.4 | CoreMark 计时 + Linux 启动 |
| FR-2.3 | UART 16550A：**既要能发（THR）也要能收（RBR + 接收中断）** | Gate 6 进 shell 执行命令 |
| FR-2.4 | PLIC 最小实现：单源（UART），`priority`/`enable`/`claim`/`complete` | 同上 |
| FR-2.5 | syscon：poweroff `0x5555` / reboot `0x7777` | 能优雅退出 |
| FR-2.6 | **misaligned load/store 由硬件分解为字节/半字访问，不抛异常** | Gate 2（`rv32ui-p-ma_data` **没有 trap handler**，抛异常直接 FAIL） |
| FR-2.7 | 取指 misaligned 仍抛 cause 0（这条与数据访问不同） | `rv32mi-p-ma_fetch` |
| FR-2.8 | 设备地址从 dtb 读取，不硬编码 | 换 dtb 仍能启动 |

**总线不变量（写进 `bus.c` 注释 + 定向测试）**：
> 先判 RAM 区间，再查设备表。
> 理由：`0x8000_0000 >> 20 & 0xFF = 0`，与 UART 同槽；`0x8200_0000 >> 20 & 0xFF = 32`，与 CLINT 同槽。若先查表会把 RAM 访问路由到设备。

### FR-3 CSR（P0）—— **这是全篇最容易漏的部分**

| 分组 | 必须实现的 CSR |
|---|---|
| **mstatus 相关** | `mstatus`(0x300)、`mstatush`(0x310，RV32 必须) |
| **trap** | `mtvec`(0x305)、`mepc`(0x341)、`mcause`(0x342)、`mtval`(0x343)、`mscratch`(0x340) |
| **中断** | `mie`(0x304)、`mip`(0x344)、`mideleg`(0x303)、`medeleg`(0x302) |
| **身份** | `misa`(0x301)、`mhartid`(0xF14)、`mvendorid`(0xF11)、`marchid`(0xF12)、`mimpid`(0xF13) |
| **计数器** | `mcycle`(0xB00)、`minstret`(0xB02)、**`mcycleh`(0xB80)**、**`minstreth`(0xB82)**、`mcounteren`(0x306)、`mcountinhibit`(0x320) |
| **PMP** | `pmpcfg0..3`、`pmpaddr0..15` |
| **未实现扩展的 trap 控制** | `mnstatus`(0x744) —— **必须能读写不报错**（riscv-test-env 的 reset 会写它） |
| **S 模式** | `sstatus`、`sie`、`stvec`、`scounteren`、`sscratch`、`sepc`、`scause`、`stval`、`sip`、`satp` |

**三条实现规则（v1.0 写错了）**：

1. **`sstatus` 不是独立寄存器**，它是 `mstatus` 的子集视图——读写 `sstatus` 的同名字段**等价于**读写 `mstatus` 的对应字段。`sie`/`sip` 同理，是 `mie`/`mip` 经 `mideleg` 掩码后的视图（未委派的位读 0、写忽略）。**物理上只有一份存储。**
2. **`mcycle`/`minstret` 是可写的 64 位计数器**（不是只读），`cycle`/`instret` 才是只读影子。RV32 必须有 `*h` 高半。写 `minstret` 要抑制该指令自身的自增。
3. **未实现的 `mstatus` 扩展字段必须 read-only 0**，不能"可写但不生效"。`FS` 在无 F 实现时 read-only 0。

**`mcounteren` 规则**：`cy`/`ir` 位为 0 时，S/U 模式读对应计数器抛 illegal；`cycle`/`instret`/`time` 是只读，写它们抛 illegal。

### FR-4 异常与中断（P0）

| 编号 | 需求 |
|---|---|
| FR-4.1 | **`mepc` = 触发 trap 的指令地址**，所有 trap 一律如此（含 ecall）。`+4` 必须由 handler 自己做——**硬件不能替它加** |
| FR-4.2 | `mtvec` 的 Direct(0) / Vectored(1) 两种模式（看低 2 位）；MODE=2/3 保留，按 WARL 归一；Vectored 下**异常仍跳 BASE**，仅中断跳 `BASE+4*cause` |
| FR-4.3 | **`mret`/`sret` 语义**：`xIE←xPIE`、**`xPIE←1`**、`xPP←U`；若从非 M 返回，**`MPRV←0`**；`sret` 另加 `SPP←0`。**不是"反向恢复"** |
| FR-4.4 | trap 进入：`xPIE←xIE`、`xIE←0`、`xPP←当前特权级` |
| FR-4.5 | `mcause`：最高位 1=中断、0=异常，低 31 位为编号 |
| FR-4.6 | `mtval` 策略（平台定义，写进文档）：illegal→指令编码；misaligned→有效地址；取指/读/写 page fault 与 access fault→**出错虚拟地址**；ecall/ebreak→0 |
| FR-4.7 | 非法 CSR 访问（地址无效或特权级不足）→ illegal instruction（cause 2）；写只读 CSR 也 → illegal |
| FR-4.8 | `mstatus.TW`/`TSR`/`TVM` 不实现则 read-only 0（不能可写不生效） |
| FR-4.9 | 异常优先级：见下方表 |

**异常优先级（单条指令内，降序）**：
```
取指断点
> 翻译期首个 page/access fault（取指）
> illegal instruction / inst-addr-misaligned / ecall / ebreak / 数据断点
> （可选）misaligned（load/store）
> 翻译期 page/access fault（数据）
> access fault（数据）
```
**注**：`inst-addr-misaligned` 由**控制流指令**触发（不是"取指时发现"），且优先级**低于** illegal 与 ecall。misaligned 与 page fault 的先后由实现自选（规范明确允许两种）。无 MMU 时不出现 page fault。

### FR-5 特权级与 MMU（P0，**Gate 4/5 就要**）

| 编号 | 需求 | 验收 |
|---|---|---|
| FR-5.1 | S 模式完整 CSR + `stvec`/`scause`/`sepc`/`sstatus`/`sret` | Gate 4（`rv32si-p-*`） |
| FR-5.2 | `medeleg`/`mideleg` 委派 | Gate 4 |
| FR-5.3 | U 模式 + M→S→U 降级 | Gate 1 起（reset 就是 `mret` 进 U） |
| FR-5.4 | **Sv32**：`satp`（MODE=bit31、ASID=30:22、PPN=21:0） | Gate 5（`rv32si-p-dirty`） |
| FR-5.5 | PTE 格式：`PPN[31:10] \| RSW[9:8] \| D \| A \| G \| U \| X \| W \| R \| V` | 同上 |
| FR-5.6 | 超页规则：非叶 PTE 的 `ppn[i-1:0]` 必须为 0，否则 page fault | 同上 |
| FR-5.7 | **A/D 位由硬件置位**（不走 Svade） | 同上 |
| FR-5.8 | `SUM` / `MXR` / `MPRV` 语义 | 同上 |
| FR-5.9 | `sfence.vma`：清 TLB / NOP，但必须合法译码；U 模式执行 → illegal | 同上 |
| FR-5.10 | U 模式页不可被 S 模式执行（"Irrespective of SUM, the supervisor may not execute code on pages with U=1"） | 迷你内核 |

### FR-6 加载器与测试 harness（P0）

| 编号 | 需求 |
|---|---|
| FR-6.1 | ELF32：遍历 program header，装载 `PT_LOAD`，按 `p_memsz` 清零 `bss` |
| FR-6.2 | **从 ELF 符号表读 `tohost`/`fromhost` 地址**（不是硬编码） |
| FR-6.3 | 监视 `tohost` 的 **store**（有 MMU 时监视物理地址）：`1`=PASS，奇数>1=FAIL（失败号 `(v-1)/2`） |
| FR-6.4 | 裸 `Image` 加载到指定地址 |
| FR-6.5 | 初始寄存器：`a0=hartid`、`a1=dtb 物理地址`、`sp` 指向栈顶、`satp=0` |
| FR-6.6 | 退出机制四种：`tohost` 写值 / syscon poweroff / `wfi` 环路检测 / `max_cycles` 超时 |

**关于 `a0` 的更正**：`RVTEST_FAIL` 会写 `a0 = (TESTNUM<<1)|1`，所以 **`a0` 不是恒为 0**。但仅靠拦截 `ecall` 读 `a0` 仍不可靠（不同测试环境的 ecall 语义不同），**正确做法是走 trap + 监视 `tohost`**。

**`wfi` 退出检测的更正**：不能用"连续 N 次相同 PC"（对 `wfi; j .` 那种两指令空转无效）。改为：PC 与上次相同**或**形成 2–3 条指令的环路，且 `mtimecmp` 不再变化。

### FR-7 迷你内核（P1）

| 编号 | 需求 |
|---|---|
| FR-7.1 | U 模式进程创建与上下文切换（≥3 个进程交替） |
| FR-7.2 | Sv32 页表 + 缺页异常处理 |
| FR-7.3 | 系统调用 ≥4 个（`write`/`exit`/`sbrk`/`fork`，`fork` 可后补） |
| FR-7.4 | 定时器中断驱动的抢占式调度 |
| FR-7.5 | shell，能加载并运行内置用户程序 |

**必须明确的一点**：没有 OpenSBI 时，**谁**把 `medeleg`/`mideleg`、`mstatus.MPP`、`stvec` 配好再 `sret` 到 S？只有两种做法，**必须选一个写进接口文档**：
- (a) 模拟器提供"启动即 S 模式 + 预置委派"的约定
- (b) 迷你内核自带一段 M 模式 stub 自己配

不选的话，S 模式的定时器中断根本进不来（`mideleg.STI` 没人设）。

### FR-8 调试与可视化（P2）

| 编号 | 需求 |
|---|---|
| FR-8.1 | 内置反汇编器（capstone 5.0.7 源码编译，**不加 `CS_MODE_RISCVC`**） |
| FR-8.2 | 单步 / 断点 / 继续 |
| FR-8.3 | 寄存器 / CSR / 内存视图 |
| FR-8.4 | 指令阶段视图（**每条指令发 5 个逻辑阶段事件**，不是"每拍"——解释器没有"拍"的概念） |
| FR-8.5 | 内存访问热图 |
| FR-8.6 | 前端形态：C 核心 → Emscripten → WASM → 浏览器 |

**关于 `CS_MODE_RISCVC` 的更正**：本项目**不做 C 扩展**，所以 capstone **不应该**加 `CS_MODE_RISCVC`。加了反而会把非法编码/数据解析成 16 位指令，产生"反汇编器比 CPU 聪明"的错位。

**事件结构更正**：v1.0 的 `stage`（单值）+ `valid`（单值）表达不了阶段视图。需改为**每条指令 5 个阶段的有效位**，或每指令发 5 个事件。

## 5. 验收门（**7 道，重排后**）

> **v1.0 的结构性错误**：我把 Gate 1 当成"基础指令"，实际上 `rv32ui-p-add` 的 reset 序列就是 `csrwi mstatus,0; csrw mepc,1f; mret`——**它在 U 模式跑**。所以第一道门就需要 trap + U 模式 + PMP 放行 + `mnstatus`/`satp` 可写。

### Gate 0 · 环境与工具链
- `riscv64-unknown-elf-gcc` 能编出 RV32IMA 目标文件并反汇编正确
- `dtc` 能把 dts 编成 dtb（头部 `d00d feed`）
- **`git init` + 远程已配置**
- **状态**：编译器与 dtc ✅ 已验证；git ❌ 未做

### Gate 1 · 最小可执行环境
**目标**：跑通 `rv32ui-p-add` 一个测试。

所需（比 v1.0 估计的多）：
- ELF 加载 + 从符号表读 `tohost`
- `mtvec`/`mepc`/`mcause` 最小实现
- `mret` + U 模式（reset 用 `mret` 落到 U）
- `mnstatus`(0x744) / `satp` 可写不报错
- PMP：不做强制（`pmpaddr0`/`pmpcfg0` 可读写）
- `tohost` 监视

**验收**：`rv32ui-p-add` 报 PASS。

### Gate 2 · RV32I
- `rv32ui-p-*` **42/42**
- 含 `ma_data`（**要求 misaligned 硬件支持**）与 `fence_i`

### Gate 3 · RV32M / RV32A
- `rv32um-p-*` **8/8**
- `rv32ua-p-*` **10/10**

### Gate 4 · 特权级与计数器
- `rv32mi-p-*` **16/16**（含 `csr`/`mcsr`/`zicntr`/`instret_overflow`/`pmpaddr`/`ma_fetch`）
- 需要：完整 CSR、`mcounteren`、`mcycleh`/`minstreth`、可写 `minstret`、`mvendorid`/`marchid`/`mimpid`、`misa=0x40141101`
- CoreMark 能跑出分数（需 UART + 时间源）

### Gate 5 · S 模式与 Sv32
- `rv32si-p-*` **6/6**
- 需要：完整 S 模式 CSR、`medeleg`/`mideleg`、**Sv32 + satp + sfence.vma + MPRV + SUM + A/D + 超页检查**、`wfi`
- **这一道门是 v1.0 最大误判**：我以为它在 Gate 5（迷你内核），实际在这里

### Gate 6 · 启动 Linux
- 出现 `Linux version ...`
- 进入 shell，能执行 ≥3 条 busybox 命令（**需要 UART 接收中断 + PLIC**）
- 与 QEMU 对照：**语义一致**（行集合一致，允许时序/地址行不同）。**不作为"逐字节一致"验收**——QEMU virt 与自写 dtb 的细节差异会导致输出不同

### Gate 7 · 迷你内核 + 可视化
- ≥3 个 U 模式进程交替
- ≥4 个系统调用
- 单步 / 断点 / 寄存器 / 内存视图 / 阶段视图可用

**累计测试**：82 = 42 + 8 + 10 + 16 + 6

## 6. 明确不做

| 不做 | 原因 |
|---|---|
| C 扩展 | riscv-tests 几乎没有 C 测试（`rv32uc` 只有一个 142 字节的 `rvc.S`） |
| F/D/B/V 扩展 | 工作量翻倍，与主线无关 |
| JIT / AOT | rv32emu 花了 15,040 行，禁区 |
| 64 位 / Sv39 | 工作量 1.5 倍 |
| 多 hart（SMP） | 单 hart |
| 内核文件系统 | xv6 的 fs 部分 2,045 行 |
| Doom / Quake | 需自定义 syscall 层，工作量不小于模拟器本体 |
| ACT4 官方认证 | 需 GCC 15 / Sail / Ruby / UDB |
| Debug Spec 实现 | 用自定义 JSON-RPC 更划算 |
| **`-v` 测试变体** | 需 newlib，且 riscv-tests 的 `-v` 规则不加 `--specs`，picolibc 救不了 |
| **自写 NOMMU 用户程序** | NOMMU 需 flat/elf2flt 格式，而 `ld` **没有** `-Wl,-elf2flt=-r` 这个选项，工具链也不带 elf2flt。只能用镜像自带的 busybox |
