# 桌面外壳对标表：Win11 / macOS 14 / GNOME 45 vs rvsim

> 用途：不是"参考一下"，是逐项判定**我们比别人好还是差**。
> 每个数值要么有来源，要么标「未查证」。我们的值全部来自对当前 `web/index.html` 的实测（Playwright `getComputedStyle` + `getBoundingClientRect`，1440×900 视口，逻辑桌面 800×600 等比缩放 1.3987）。
>
> 判定标记：`✅ 对齐` / `⚠️ 偏差`（有值但不对） / `❌ 缺失`（别人有我们没有） / `➕ 超出`（我们做了别人没做的）

---

## 0. 方法与可信度

| 平台 | 可信度 | 说明 |
|---|---|---|
| Windows 11 | 高 | 圆角/标题栏/任务栏有官方设计文档；窗控按钮尺寸取自微软自家仓库源码（microsoft/terminal `MinMaxCloseControl.xaml`）；拖动阈值、最小窗口尺寸为本机 `GetSystemMetricsForDpi` 实测 |
| macOS 14 | 低 | Apple HIG 基本不给像素值。圆角 ≈10px、红绿灯 12pt 均为第三方测量，已标注 |
| GNOME 45 | 高 | libadwaita 1.4.0 与 gnome-shell 45.0 的 scss 常量可直接引用，几乎每项都有源码行号 |
| 性能 | 中 | **三个平台都没有公开的 UI 帧率/输入延迟数值**。唯一可对标的是 Web 的 RAIL 基线，本表用它 |

**一句话结论先放这里**：在"像素级规格"上我们和 Win11 差得不多（圆角 8px、标题栏 32px、窗控 46×32 都对得上），差的是**三样东西**：动效没有阶梯（18 档散值）、滚动历史差 40 倍、以及一批"别人有我们完全没有"的交互（双击选词、Alt 块选、拖动阈值、失焦态、Snap 布局）。

## 7. 修复顺序

1. **动效阶梯**（P0-1）：18 档 → 4 档，全局替换。风险低、收益最大（一致性）。
2. **最大化圆角 + 失焦态**（P0-2/3）：两个 CSS 状态，10 分钟。
3. **拖动阈值**（P0-4）：拖动逻辑加 4px 判定。
4. **scrollback 提到 2000 行**（P0-5）：改一个宏 + 宿主渲染上限。
5. **ANSI 16 色**（P0-6）：内核加属性字节，宿主按属性上色（比现在的启发式更准）。
6. **Alt+Tab + 最小化/最大化动画**（P1-8/9）。
7. **终端交互补全**（P1-12~15）：双击选词、查找、链接、快捷键。

## 5d. 对比度实测（WCAG 2.x）

| 组合 | 实测 | 要求 | 结论 |
|---|---|---|---|
| 正文 `#FFFFFF` / `--s0` | **18.13 : 1** | ≥4.5 | ✓ |
| 正文 / `--s1` | 16.55 : 1 | ≥4.5 | ✓ |
| 正文 / `--s2` | 15.22 : 1 | ≥4.5 | ✓ |
| 正文 / `--s3` | 13.48 : 1 | ≥4.5 | ✓ |
| 次要 `.77` / `--s0` | 10.94 : 1 | ≥4.5 | ✓ |
| 次要 / `--s2` | 9.57 : 1 | ≥4.5 | ✓ |
| 三级 `.53` / `--s0` | 5.76 : 1 | ≥3.0 | ✓ |
| 强调 `#2DD4BF` / `--s0` | 9.74 : 1 | ≥3.0 | ✓ |
| 描边 `.07` / `--s0` | 1.20 : 1 | ≥3.0 | ✗ |

描边不达标，但这是**照 Win11 的 Fluent token 抄的**（`ControlStrokeColorDefault #12FFFFFF` = 0.0706）。Windows 自己也不达 3:1，属于它的设计取舍。WCAG 1.4.11 约束的是"识别控件所必需的视觉信息"，装饰性分隔线不受约束；输入框在 focus 时切到强调色（9.74:1），和 Fluent 的实际做法一致。
