# rvsim 接口文档

本文档回答需求文档 FR-7 底部提出的问题：**没有 OpenSBI 时，谁把 `medeleg` / `mideleg` / `mstatus.MPP` / `stvec` 配好再 `sret` 到 S 模式？**

并集中记录模拟器与内核之间的约定、系统调用接口、设备映射。

---

## 1. M 模式启动约定：方案 (b)

需求文档给出两个选项：

- (a) 模拟器提供「启动即 S 模式 + 预置委派」的约定
- (b) 迷你内核自带一段 M 模式 stub 自己配

**本项目选择 (b)。** 理由：

1. 模拟器保持「裸机复位」语义——`pc = 0x80000000`、`priv = M`、所有 CSR 为复位值。这样跑 riscv-tests 时行为与真实硬件一致，不需要在模拟器里塞特权级特判。
2. 委派配置是**操作系统策略**而非硬件行为，放内核里更合理。
3. 同一个模拟器既能跑不带 OS 的测试，也能跑自带 stub 的内核，互不干扰。

### 1.1 复位状态（模拟器保证）

| 项 | 值 |
|---|---|
| `pc` | `0x8000_0000` |
| 特权级 | `M` |
| `misa` | `0x40141101`（MXL=1, U/S/M/I/A） |
| `mstatus` | `0` |
| `medeleg` / `mideleg` | `0` |
| `satp` | `0`（不分页） |
| `mtimecmp` | 全 1（不会立刻触发定时器） |
| 内存 | RAM `0x8000_0000` + 64 MB 清零 |

### 1.2 内核 M 模式 stub 做的事

`kernel/start.S` 的 `_start`：

```
csrw mstatus, zero        # 清 MPP 等
csrw mie, zero
la   sp, stack_top
csrw mscratch, sp         # M 模式 trap 换栈用
la   t0, m_trap_entry
csrw mtvec, t0
li   t0, 0x0000B1FF
csrw medeleg, t0          # 委派常见异常给 S（但不含 ecall from S）
li   t0, 0x00000222
csrw mideleg, t0          # 委派 SSIP|STIP|SEIP
清零 .bss
call kmain
```

**两个关键位必须理解：**

**`medeleg = 0xB1FF`** —— bit 9（ecall from S）**故意不委派**。这样 S 模式发 `ecall` 时会 trap 到 M 模式，用来实现 SBI 调用（本项目的 `SSIP` 自定义调用靠它清 `mip.STIP` 并重装定时器）。

**`mideleg = 0x222`** —— 委派 bit 1（SSIP）、bit 5（STIP）、bit 9（SEIP）。**不委派 STIP 的话，S 模式的定时器中断根本进不来。**

### 1.3 进 S 模式

`kernel/s_entry.S` 的 `enter_s_mode(entry, stack)`：

```
csrw mepc, a0             # entry = s_main
mv   sp, a1               # S 模式栈
csrc mstatus, 0x1800      # MPP = 0 (U)... 之后会被改成 S
csrs mstatus, 0x0800      # MPP = S
csrc mstatus, 0x20000     # MPRV = 0
la   t2, s_trap_entry
csrw stvec, t2            # S 模式 trap 入口
la   t2, s_kstack_top
csrw sscratch, t2
csrc mstatus, 0x2         # 清 SIE
li   t1, 0x80
csrs mstatus, t1          # MPIE = 1
mret
```

**`MPIE = 1` 是必须的**：`mret` 会把 `MIE ← MPIE`。不置 `MPIE` 的话，`mret` 后 `MIE = 0`，定时器中断永远不会触发——这个 bug 排查了很久。

### 1.4 进 U 模式

`enter_u_mode(entry, stack, pid)`：

```
csrw sepc, a0
mv   sp, a1
mv   a0, a2               # a0 = pid，用户程序靠它区分自己
csrc sstatus, 0x100       # SPP = 0 -> U
csrs sstatus, 0x40000     # SUM = 1（让 S 模式能读用户内存）
csrs sstatus, 0x20        # SPIE = 1
sret
```

**`SPIE = 1` 也是必须的**：`sret` 会把 `SIE ← SPIE`。不置的话，进 U 模式后 S 中断永久关闭。

## 2. trap 与栈帧约定

### 2.1 栈帧布局（M 与 S 统一）

两个 trap 入口都用同一套布局，共 128 字节：

| 偏移 | 内容 |
|---|---|
| 0 | `x1` (ra) |
| 4 | `x2` (sp，存的是**被中断时的 sp**，不是栈帧指针) |
| 8 | `x3` (gp) |
| ... | ... |
| `(N-1)*4` | `xN` |

**注意：`xN` 存在偏移 `(N-1)*4`，不是 `N*4`。** 所以 `a0`（x10）在索引 9、`a7`（x17）在索引 16。内核里用 `R_A0` / `R_A1` / `R_A7` 宏，**不要直接写 `regs[10]`**。

### 2.2 换栈

- M 模式 trap：`csrrw sp, mscratch, sp`，`mscratch` 在启动时初始化为 M 栈顶
- S 模式 trap：`csrrw sp, sscratch, sp`，`sscratch` 在 `enter_u_mode`/`enter_s_mode` 时设为 S 栈顶

### 2.3 定时器中断链路

```
CLINT mtime >= mtimecmp
        ↓
   M 模式收到 MTIP (cause = 0x80000007)
        ↓
   m_trap_handler: 把 mtimecmp 推到远未来 + 置 mip.STIP
        ↓
   mret 回原模式
        ↓
   S 模式收到 STI (cause = 0x80000005，因为 mideleg 委派了)
        ↓
   s_trap_handler: 保存 32 个寄存器 → 调度 → 切 satp → ecall(SBI 'SSIP')
        ↓
   M 模式处理 ecall: 清 mip.STIP + 重装 mtimecmp
        ↓
   返回新的 pc，sret 到新进程
```

**为什么不用 M 模式直接切进程**：M 模式 trap 和 S 模式 trap 用两套栈帧，混用会导致寄存器保存/恢复错位。统一在 S 模式切最干净。

## 3. 系统调用接口

用户程序通过 `ecall` 调用，`a7` 是调用号，返回值放 `a0`。

| 号 | 名称 | 参数 | 返回 |
|---|---|---|---|
| 0 | `exit` | `a0` = 退出码 | 不返回 |
| 1 | `write` | `a0` = buf, `a1` = len | 写入长度 |
| 3 | `getpid` | — | 当前 pid |
| 4 | `yield` | — | 0 |
| 5 | `sbrk` | `a0` = 增量（可为负） | 旧堆顶，失败返回 -1 |
| 6 | `fork` | — | 父：子 pid；子：0；失败：-1 |

### 3.1 sbrk 的堆布局

每个进程有独立的 64 KB 堆区：

```
基址 = 0x8060_0000 + pid * 0x1_0000
上限 = 0x8080_0000
```

`brk` 初始为 0（表示未初始化），首次调用时设成基址。新增的页通过 `vm_page_fault_on` 映射到**当前进程自己的页表**。

### 3.2 fork 的语义

- 复制 PCB（含 32 个寄存器、pc、brk）
- 复制用户地址空间中**已映射的所有页**到新物理页（写时复制没做，是完整复制）
- 子进程的 `pgtbl` 是新建的独立页表
- 子进程 `a0 = 0`，父进程 `a0 = 子 pid`
- 进程槽不足（`NPROC = 5`，初始 3 个）时返回 -1

## 4. 内存与设备映射

### 4.1 地址空间

| 区域 | 范围 | 权限 |
|---|---|---|
| 内核代码/数据 | `0x8000_0000` – `0x803F_FFFF` | M/S，恒等映射 |
| 用户程序代码 | `0x8040_0000` – 起始页 | U，可执行 |
| 用户栈 | `0x8041_0000` 起，每进程间隔 8 KB | U，按需分配 |
| 用户堆 | `0x8060_0000` + pid×64 KB | U，按需分配 |

### 4.2 设备

| 设备 | 基址 | 说明 |
|---|---|---|
| CLINT | `0x0200_0000` | `mtimecmp` @ `+0x4000+8*hart`，`mtime` @ `+0xBFF8` |
| PLIC | `0x0C00_0000` | context 块 `+0x0` 阈值、`+0x4` claim/complete |
| UART | `0x1000_0000` | ns16550a，PLIC source 10 |
| syscon | `0x0010_0000` | 写 `0x5555` 关机 |

### 4.3 页表约定

- 每个进程有独立页表根；内核映射（RAM / UART / CLINT / syscon）在各进程间**共享**
- 用户区 L1 独立，初次只映射代码页
- 缺页处理用**当前进程**的页表（`procs[cur_proc].pgtbl`），不是 `g_kroot`
- 切 `satp` 后必须 `sfence.vma`

## 5. shell 命令

| 命令 | 作用 |
|---|---|
| `help` | 列出命令 |
| `ps` | 显示进程表（PID / 状态 / 运行次数 / PC） |
| `run` | 启动内嵌用户程序（3 个进程，抢占式轮转） |
| `mem` | 显示物理内存大小与缺页次数 |
| `uptime` | 显示 CLINT mtime |

**当前状态说明**：`s_main` 默认直接调度并进入用户程序（便于演示抢占调度）。要进 shell 交互，把 `s_main` 里 `proc_schedule()` / `enter_u_mode` 那两行注释掉重新编译即可——shell 的代码路径完整可用（`help` / `ps` / `mem` / `uptime` 均已实测）。

## 6. 模拟器命令行接口

```
rvsim --elf <file>              加载 ELF（裸机程序或内核）
rvsim --image <file>            加载裸二进制（Linux Image）
rvsim --dtb <file>              加载设备树
rvsim --max-cycles <N>          指令数上限
rvsim --disasm <addr> <count>   运行结束后反汇编（capstone）
rvsim --dump-mem <addr> <len>   运行结束后 dump 物理内存
```

环境变量：

| 变量 | 作用 |
|---|---|
| `RVSIM_TRAP=1` | 打印每次 trap 的 cause / tval / epc |
| `RVSIM_IGNORE_MIE=1` | 忽略 M 模式 MIE 检查（调试用） |
